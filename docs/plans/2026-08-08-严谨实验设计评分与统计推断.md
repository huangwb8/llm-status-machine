# 严谨实验设计、质量评分与统计推断实施计划

## 问题是什么

- **当前现象：** 项目已经能把 Prompt、runtime、workspace 和执行过程冻结成可审计的 TrialPlan，并完整保存每个 episode 的原始输出、文件变化和 seal；但 `matched_pair`、`block` 和 `branch` 的实验语义仍较薄，内置 scorer 只检查执行是否完整，CSV 导出也不能直接用于组间比较。
- **影响：** 研究者能够证明“模型当时做了什么”，却还不能仅依靠项目回答“Prompt A 是否比 Prompt B 更好、差异有多大、不确定性多高、评分是否可靠”。若直接从现有导出做显著性检验，容易出现顺序混杂、伪重复、失败样本被静默排除、事后挑指标或使用错误检验等问题。
- **已知原因：** StudySpec 只有提示词、重复数和较粗的 design 枚举，没有冻结研究假设、比较组、主要结局、缺失值策略和随机化算法；Trial 没有显式的比较集、配对或区组标识；评分协议没有可插拔且可固定身份的质量 scorer；统计数据集和推断结果也没有独立的 schema 与 provenance。
- **风险等级：** 高。该改动会跨越 StudySpec、TrialPlan、runner、evaluation、export、CLI 和存储契约；任何默认值不清或迁移不完整，都可能让旧实验被错误解释为新的确认性实验。

## 要达到什么目标

- **完成后的变化：** 用户可以在运行前声明确认性或探索性研究、主要质量指标、Prompt 对照、缺失和失败处理方式以及显著性水平；编译器生成平衡、可复核、版本化的随机执行序列；sealed episode 可以在不暴露处理标签的情况下批量评分；项目最终输出一行一个 episode 的分析数据集、效应量、置信区间、随机化检验、校正后的显著性结果和可读报告。
- **研究单位明确：** episode 是唯一的随机化和推断单位。subagent、token、测试用例、评分维度和重复评委都不能被误当成额外独立样本。
- **证据链不断裂：** RawBundle 继续保持不可变；评分和分析都是派生层，每个结果都能追溯到 TrialPlan、bundle seal、scorer 身份、分析配置和软件版本。
- **默认行为保守：** 条件不满足确认性推断时，CLI 应拒绝给出确认性结论或明确降级为描述性结果，不能仅打印一个 p 值后让用户自行猜测有效性。
- **兼容既有数据：** 旧 StudySpec、TrialPlan、RawBundle 和 `deterministic-v1` 评分仍可读取和验证；旧记录不会被重写或自动宣称为确认性研究。

## 不在本次处理范围

- 不把 Web UI、HTTP API、云端控制面或分布式调度重新带回首版 Python CLI。
- 不承诺冻结远端模型权重、供应商路由和不可见系统 Prompt；报告只陈述实际能记录的 endpoint 与服务端元数据。
- 不在首轮实现任意统计模型公式、贝叶斯建模、因果中介分析或自动选择“最显著”模型。
- 不把多模型、多 runtime 和多 workspace 扩展为同一个 StudySpec 的通用实验轴；本计划先把“固定其它条件，只比较 Prompt”做严谨。
- 不内置特定厂商的 LLM-as-judge。语义评委通过统一的外部 scorer 协议接入，其 runtime、rubric 和输出仍需冻结与审计。

## 核心决策

### 区分探索性研究与确认性研究

新增 `study_mode: exploratory | confirmatory`。既有 v1 配置迁移后默认是 `exploratory`，避免旧实验被追认成预注册研究。

确认性模式必须在编译前满足以下门禁：

- 使用 `state_policy=independent`，避免后一轮继承前一轮结果；`carry_forward` 和当前语义较弱的 `branch` 只能做探索性描述。
- 冻结至少一个主要 outcome 和一个预先声明的 Prompt contrast。
- 明确失败/超时、scorer 失败和缺失值怎样进入主要分析；不得默认删除失败 episode。
- 使用版本化随机化算法和固定 seed，并把比较集、区组、序列位置和随机化 draw 写进 Trial。
- 首版确认性运行使用 `concurrency=1`。有界并发继续可用于探索性实验；以后只有在实现批次平衡并记录资源竞争后，才放宽确认性并发。
- 所有确认性指标必须指定量纲、取值范围、方向和聚合规则，防止评分后再改变“越高越好”或权重。

### 预注册的是分析意图，不只是 Prompt 列表

StudySpec 增加冻结的 `evaluation` 和 `analysis` 配置：

- `evaluation` 声明 scorer、评分输入、rubric/support 文件摘要、评分重复数、聚合方法和预期 metrics。
- `analysis.outcomes` 声明主要/次要指标、指标类型、方向、失败值和缺失策略。
- `analysis.contrasts` 明确 treatment Prompt、control Prompt、outcome、估计量和多重比较 family。
- `analysis.alpha`、随机化次数、bootstrap 次数、分析 seed 和多重比较方法必须进入 plan identity。

编译完成后，runner、scorer 和 inference engine 都只读 TrialPlan 中的冻结配置，不在执行时重新读取“最新 rubric”或临时增加比较。

### 采用设计型推断，避免自动统计黑箱

首版只支持预先声明的 Prompt 两两对照，并根据设计自动选择固定算法，不允许根据数据分布事后挑检验：

| 设计 | 点估计 | 置信区间 | 零假设检验 | 随机化限制 |
| --- | --- | --- | --- | --- |
| `full_factorial` 独立对照 | 两臂均值差或风险差 | 分层 bootstrap | 标签置换 | 只在相同 condition strata 内置换 |
| `matched_pair` | pair 内差值的均值 | pair bootstrap | pair 内 sign-flip / swap | 每个 pair 必须同时包含 treatment 与 control |
| `block` | 按有效随机化单位加权的 block 内差值 | block-aware bootstrap | block 内标签置换 | 标签不得跨 block 交换 |

连续指标同时报告原始量纲差值和标准化效应量；二元指标报告风险差。推断结果必须同时包含计划样本数、成功运行数、有效评分数、失败数、缺失数、效应量、区间、原始 p 值和校正后 p 值。默认使用 Holm 方法校正同一 family 中的多个确认性 contrast。

小样本或设计不完整时仍可输出原始数据与描述性统计，但应给出机器可读 warning，并将 `confirmatory_valid=false`，而不是制造精确但不可信的结论。

## 改进方向

### 把实验设计编译成可审计的比较结构

Trial 增加下列字段，使“谁与谁比较”不再依赖事后从 Prompt ID 猜测：

- `arm_id`：当前 Prompt revision 的实验臂标识。
- `comparison_set_id`：相同 repetition、condition 和 block 下应共同比较的一组 Prompt。
- `pair_id`：仅 matched-pair 使用；每个 pair 必须有且只有声明 contrast 所需的两臂。
- `block_id`：稳定标识 block；不再只保存一个可能重复的任意字典。
- `sequence_position` 与 `dispatch_batch`：区分计划顺序、比较集内顺序和实际调度批次。
- `randomization`：保存算法名、算法版本、seed 派生值和 draw 序号。

编译器先构造 comparison sets，再随机化 set 顺序和 set 内 arm 顺序。两臂 matched-pair 使用平衡的 AB/BA 顺序；多 Prompt full-factorial 使用 seed 决定的循环平衡顺序，避免某个 Prompt 总在时间序列末端。若 repeats 不足以形成平衡序列，确认性模式直接失败，探索性模式给出诊断。

`lsm study validate` 和 `lsm study compile --json` 增加 design diagnostics：每臂样本数、每个 pair/block 的完整性、顺序平衡、预计失败处理、主要 contrasts 以及是否满足确认性门禁。

### 建立独立、盲化且可版本化的质量评分层

把现有 `deterministic-v1` 明确改称“执行完整性评分”，保留兼容别名，但不再把它描述为回答质量。

新增统一 ScorerSpec 和 scorer runner：

- 内置 scorer 用于执行完整性、基础资源指标和可确定的 oracle 测试。
- 外部 command scorer 采用声明式 argv，不经过 shell；其 executable、版本、SHA-256、rubric 文件和 support files 都在评估前固定。
- scorer 只接收临时只读 staging 目录和最小 manifest。默认不给 Prompt ID、arm、condition、ordinal 或其它 treatment 标签；需要判断指令遵循时可以显式接收实际 Prompt 文本，但报告必须提示文本本身可能使评委推断出处理组。
- 每个 run 生成与 treatment 无关的 `blind_id`。评分结果先以 blind ID 保存，所有计划内评分完成后再通过 run-level blinding map 合并 treatment。
- scorer 输出使用严格 JSON schema：状态、metric ID、数值/类别、上下界、方向、evidence references、scorer 版本、耗时和错误。非法 JSON、越界分数、缺失必需 metric、超时和非零退出码均成为一等 evaluation outcome。
- 评分前后都验证 RawBundle seal；scorer 永远不能写回 RawBundle。需要评分最终代码时，从 sealed Git commit 导出临时快照，并核对 snapshot manifest。

主观 rubric 支持多个独立评分重复，但推断前先按预注册规则聚合到 episode 层，不能把多个评委当成多个实验样本。报告同时给出评分覆盖率和一致性；首版实现 Krippendorff's alpha，按指标类型选择 nominal、ordinal 或 interval distance。若确认性主指标依赖主观评分但没有达到预注册的一致性阈值，结论降级并保留全部原始评分。

### 生成稳定的一行一个 episode 分析数据集

新增 run-level observation builder。它只读取 plan、run/episode manifest、有效 seal 和计划内 evaluation，并生成：

- `observations.jsonl`：无损、类型稳定的事实数据源。
- `observations.csv`：便于 R、Python 和电子表格使用的扁平视图。
- `dataset-manifest.json`：输入 bundle/evaluation 摘要、列 schema、生成器版本和整表 SHA-256。

每行至少包含 run/episode ID、arm、Prompt revision、repetition、condition、block/pair/comparison set、计划与实际顺序、episode 状态、四类 outcome、墙钟时间、token/usage（可获得时）、变更文件数、每个原始和聚合 metric，以及所有缺失/失败原因。

builder 必须执行完整性检查：一个 episode 恰好一行、计划内 episode 不得消失、额外 episode 不得混入、pair/block 不得错配、同一 metric 类型不得漂移。失败和超时始终保留在表中；是否赋予 worst-case 值由预注册 outcome policy 决定。

现有 `export run --format csv` 保持兼容；另加明确的 research export，避免悄悄改变旧 CSV 字段。

### 实现可复算的统计推断与功效检查

新增 analysis engine，输入只能是 dataset manifest 和 TrialPlan 内冻结的 AnalysisSpec。每次分析产生稳定 analysis ID，并保存：

- `results.json`：完整估计量、区间、检验、样本流失、warnings 和有效性状态。
- `report.md`：面向研究者的结果摘要，先报告效应量与不确定性，再报告显著性。
- `analysis-manifest.json`：analysis spec、输入摘要、算法版本、随机 seed、依赖版本和所有输出摘要。

随机化检验在可枚举时做 exact test，组合数过大时使用预注册 seed 的 Monte Carlo permutation，并报告实际 permutation 数和 Monte Carlo 精度。bootstrap 使用独立的 analysis seed，并按 comparison set/pair/block 重采样，禁止拆散设计单位。

增加轻量的事前 power/sensitivity 命令，只覆盖首版支持的两臂连续指标和二元指标。用户必须显式给出最小有意义效应、方差或基线率；工具输出假设和所需 episode 数，不自动替用户选择效应。复杂多因素功效分析明确引导到外部统计工具。

统计实现优先使用成熟库而不是手写分布函数。将 `numpy` 和 `scipy` 放入独立 `analysis` optional dependency；未安装时，设计、运行和评分仍可工作，分析命令给出明确安装提示。核心估计和随机化逻辑仍由项目封装并用固定数据与独立参考结果交叉验证。

### 让 CLI 呈现完整研究生命周期

保持现有命令不破坏，同时增加以下稳定入口：

- `lsm evaluate run <run-id>`：执行计划内全部 scorer，支持 `--json`，可安全重复，已完成且输入摘要一致时幂等复用。
- `lsm research dataset <run-id>`：构建 observations 与 dataset manifest。
- `lsm research infer <run-id>`：执行预注册 contrasts，默认拒绝未评分、seal 无效或设计门禁失败的确认性分析。
- `lsm research report <analysis-id>`：读取已有结果生成或重建 Markdown，不重新估计。
- `lsm study power <study.yml>`：根据显式假设做基础功效或敏感度检查。

所有 `--json` 输出使用固定 schema，并区分 `status`、`confirmatory_valid`、`warnings` 和 `errors`。人类可读输出不得只展示“显著/不显著”，必须显示 effect、CI、n 和失败/缺失信息。

### 分离 schema 版本并兼容历史实验

当前单个 `SCHEMA_VERSION` 同时服务多个契约，新增研究层后应拆分为 Study、TrialPlan、RawBundle、Event、Evaluation、Analysis 和 Index 各自版本。RawBundle v1 不因新增外部评分而升级。

迁移策略采用“读取时显式升级、原文件不重写”：

- v1 StudySpec 可加载为 v2 exploratory spec，并记录 migration warning。
- v1 TrialPlan 继续按原顺序运行；不伪造 pair/block/randomization metadata，也不能执行确认性 inference。
- 旧 `deterministic-v1` evaluation 继续可读，但映射为 execution-integrity metric。
- SQLite 仍是可重建索引；新增 evaluation/analysis 查询表时必须可从文件 manifest 完整 reindex。
- 新版写入只产生新 schema，任何不认识的未来 schema 均早期失败，不能静默忽略字段。

### 用一个真实示例证明通用层能替代一次性脚本

将 `examples/subagent-count-quality-study` 迁移为首个端到端示例：

- 把现有 oracle scorer 包装成统一 command scorer，保持 blind-before-unblind 和 sealed commit 校验。
- 用 AnalysisSpec 表达 intention-to-treat 质量分、失败归零和预注册 Prompt contrasts。
- 由通用 dataset builder 生成现有 R 分析需要的 tidy 表；R Markdown 可以继续负责高级可视化，但不再自行解析 RawBundle 或重建 treatment join。
- 保留现有 pilot 的描述性结论，不能因为新引擎上线而给只有每臂一次的旧数据补做确认性推断。

## 实施范围与顺序

### 数据契约与兼容读取

先拆分 schema 版本，加入 DesignSpec、EvaluationSpec、AnalysisSpec、OutcomeSpec、ContrastSpec 和新的 Trial assignment 字段，同时完成 v1 读取兼容。此阶段只改变“如何准确表达研究”，不急于运行统计。

完成标志是：新旧 StudySpec/TrialPlan 都能明确验证；新计划包含完整预注册与随机化 provenance；旧计划仍能运行但被标记为 exploratory。

### 随机化编译器与运行时观测

随后重构 compiler，使其先构造 comparison sets，再执行版本化平衡随机化；runner 补充实际开始/结束时间、调度批次和设计偏离记录。确认性门禁必须在启动模型之前完成。

完成标志是：相同 spec/seed 字节级稳定，不同 seed 改变允许改变的顺序，AB/BA、pair 和 block 平衡通过性质测试，运行时偏离不会被隐藏。

### 评分协议与批量评分

在稳定 TrialPlan 上实现 scorer registry、pinned command scorer、盲化 map、只读 staging、evaluation seal/provenance 和 run-level CLI。先支持确定性 oracle 与结构化 rubric 输出，再加入多评分重复和一致性统计。

完成标志是：示例 oracle 不再需要自定义 bundle 遍历；篡改 bundle、rubric 或 scorer binary 都会导致评分失败；重复评分不会覆盖不同版本结果。

### 数据集与设计型推断

评分契约稳定后再实现 observation builder、缺失/失败策略、预注册 contrast、bootstrap/permutation、multiplicity 和报告。推断代码不得直接遍历可变 workspace，只能消费经过 manifest 校验的数据集。

完成标志是：固定小数据集与独立 SciPy/R 参考值一致；置换 seed 可复算；paired、blocked 和 unpaired 数据不会误用同一算法；样本不足时只给描述性结论。

### CLI、文档、示例和收尾验证

最后统一 JSON 输出、README、`docs/how-it-works.md`、架构说明、示例和 CHANGELOG；把专用示例评分逻辑迁移到通用层，并完成全量回归、构建与核心冒烟。

## 如何确认完成

### 用户可观察的验收结果

- 一个包含两个 Prompt、matched-pair、显式主要质量指标和 contrast 的 confirmatory StudySpec 可以通过验证并生成平衡 AB/BA 的冻结计划。
- 同一个 spec 与 seed 重编译得到完全相同的 plan；改变 seed 只改变允许随机化的顺序，不改变样本数、Prompt 内容或 comparison membership。
- confirmatory 模式使用 `carry_forward`、未声明失败处理、缺少主要指标、pair 不完整或并发大于 1 时，在启动任何 runtime 前失败。
- `evaluate run` 对所有 sealed episodes 进行盲化评分，保留 scorer/rubric 摘要与每次评分 outcome；评分不会改变 RawBundle seal。
- research dataset 恰好一行一个计划 episode，失败和超时不会消失，Prompt arm、pair/block、顺序、质量、成本和缺失原因可直接用于 R/Python。
- inference 结果同时报告 effect、CI、原始和校正 p 值、planned/observed n、失败/缺失以及 `confirmatory_valid`，并可由同一输入和 seed 复算。
- 旧 run 仍可查看、验证、导出和执行原评分，但 research infer 会清楚标记其没有预注册确认性契约。

### 自动化验证矩阵

| 范围 | 必须覆盖的行为 |
| --- | --- |
| Domain validation | 唯一 Prompt/scorer/outcome/contrast ID；合法 metric 类型和范围；确认性门禁；未来 schema 拒绝 |
| Compiler properties | seed 稳定性；臂数平衡；AB/BA 平衡；pair/block 完整；输入顺序不影响身份；不同并发不改 assignment |
| Runner integration | 实际时间与调度记录；设计偏离；失败/超时仍 seal；source workspace 不变 |
| Scorer protocol | pin 校验；只读 staging；blind manifest；非法/越界输出；超时；多评分聚合；seal 前后不变 |
| Dataset integrity | 每个计划 episode 一行；无重复/漏行；类型稳定；ITT 失败值；metric 缺失原因；manifest 篡改检测 |
| Statistical correctness | unpaired/paired/blocked 固定样例；exact 与 Monte Carlo permutation；bootstrap seed；Holm 校正；小样本降级 |
| Compatibility | v1 Study/Plan/Bundle/Evaluation；旧 CLI 输出；index reindex；未知新 schema 早期失败 |
| Black-box CLI | 每个新命令的成功、可纠正错误和 `--json` 契约；缺 analysis extra 的安装提示 |

实现收尾必须运行：

```bash
uv sync --frozen --extra test --extra analysis
PYTHONDONTWRITEBYTECODE=1 uv run pytest
uv build
uv run lsm smoke --root "tmp/core-smoke-$(date +%Y%m%d-%H%M%S)" --json
```

此外新增一个无需密钥的 research smoke：Simulator、两个 Prompt、至少四个 comparison sets、`independent + concurrency=1`，完成 compile → run → blind evaluate → dataset → infer → report，并验证所有 manifest 和 seal。

## 风险与应对

- **确认性外观掩盖低质量设计：** 使用硬门禁和 `confirmatory_valid`，不允许仅靠配置名称宣称严谨；报告始终展示设计诊断和样本流失。
- **评分泄露处理组：** 默认隐藏 Prompt ID、arm、condition 和顺序；对必须读取实际 Prompt 的 scorer 显示无法完全盲化的限制。评分完成前不生成 treatment join。
- **失败值影响结论：** 每个主要 outcome 必须预注册失败/缺失策略，并同时报告原始完成率与敏感度结果；不得静默 complete-case 分析。
- **远端模型漂移：** 保存可获得的 model ID、base URL、runtime、服务端 metadata 和时间 block；报告明确其不是模型权重快照。跨时间运行建议把时间窗设为 block。
- **统计实现错误：** 限制首版 estimand 和设计范围，使用 SciPy 原语，固定参考数据与 R/SciPy 交叉核验，不实现自动模型选择。
- **依赖膨胀：** 统计库放入 `analysis` extra；核心 runner、recorder 和 seal 验证保持轻量。
- **旧 schema 被误迁移：** 只在内存生成明确的 legacy exploratory view，不覆盖历史文件；迁移 warning 进入 JSON 和报告。
- **索引与文件事实不一致：** evaluation 和 analysis manifest 继续作为事实来源，SQLite 只做可重建查询索引。

## 技术补充（按需阅读）

### 建议的数据对象边界

| 对象 | 责任 | 是否进入冻结计划 |
| --- | --- | --- |
| `DesignSpec` | 研究模式、随机化策略、比较集和确认性门禁 | 是 |
| `ScorerSpec` | scorer 身份、pin、输入、rubric、metrics 与重复评分 | 是 |
| `OutcomeSpec` | 主要/次要指标、类型、方向、失败和缺失策略 | 是 |
| `ContrastSpec` | treatment/control、estimand、family 与推断方法 | 是 |
| `EvaluationRecord` | 单次 blind scorer 结果与 provenance | 否，运行后派生 |
| `ObservationDataset` | episode 层事实表及其 manifest | 否，运行后派生 |
| `AnalysisResult` | 设计型估计、区间、检验、warnings 和有效性 | 否，运行后派生 |

### 建议的文件边界

- `domain/` 拆出 design、evaluation 和 analysis model，避免继续膨胀单个 `models.py`。
- `study/compiler.py` 只负责构造 comparison sets、随机化和冻结计划；统计算法不得进入 compiler。
- `evaluation/` 分为 contracts、registry、runner、builtin 和 agreement；现有 scorer 迁移为 builtin execution-integrity。
- 新增 `analysis/`，分为 dataset、estimators、randomization、multiplicity、power 和 report。
- `recording/` 与 RawBundle seal 逻辑原则上不改，只增加供派生层安全读取 sealed snapshot 的公共函数。
- `storage/index.py` 只增加可重建的 evaluation/analysis 查询入口，不存唯一事实。
- `cli/app.py` 注册 `research` 子命令；随着命令增长，可把子命令实现拆到 `cli/` 独立模块，避免单文件继续扩大。

### 派生数据目录

```text
.lsm/runs/<run-id>/
  blinding/map.json
  episodes/<episode-id>/evaluations/<evaluation-id>/
    evaluation.json
    stdout.raw
    stderr.raw
    manifest.json
  research/datasets/<dataset-id>/
    observations.jsonl
    observations.csv
    dataset-manifest.json
  research/analyses/<analysis-id>/
    results.json
    report.md
    analysis-manifest.json
```

blinding map 不属于公开 scorer 输入；archive 导出应默认包含它以便完整复核，research dataset 导出则只提供完成解盲后的必要字段，不携带凭据或环境值。

### 停止条件

首版在以下能力完成后停止扩展：两个或多个 Prompt 的独立 episode、full-factorial/matched-pair/block 三种设计、确定性或外部质量 scorer、episode 层 dataset、连续/二元两类 outcome、预注册两两 contrasts、设计型 CI/检验、Holm 校正和 Markdown/JSON 报告。更复杂模型必须由真实研究需求和独立 ADR 触发，不能在本计划中预建。
